Sonicfast 0.15.0 adds network audio outputs and a built-in synchronized Snapcast receiver.

- Send the currently playing music to a Snapserver TCP source. Existing EQ,
  limiting and visualizations remain active; source PCM is 44100 Hz, 16-bit stereo.
- Receive PCM/FLAC Snapcast streams directly in Sonicfast, without installing
  `snapclient`. Includes clock synchronization, timestamped buffering,
  device-latency compensation, drift correction and reconnection.
- Configure sending and receiving independently in Settings → Snapcast. Receiving
  is also available from the sign-in screen, without a music-server account.
- Output changes apply automatically and preserve the track, position and
  play/pause state, including a song that is still loading. Fingerprint and
  endpoint edits apply after a short typing pause, with visible validation.
- Receive-only Snapcast mode clearly warns that the Local queue is paused.
  Choosing Local turns Receive off; enable Send and Receive together to hear
  your own source through the synchronized receiver.
- Add Docker interoperability tests and a separate manual smoke playground with
  Snapserver, Snapweb, independent reference clients and optional synthetic tones.

- Choose Local, AirPlay Classic, Chromecast or Snapcast from the player output
  picker. Discover nearby receivers or configure a host and port manually.
- Send processed audio to password-free, unencrypted AirPlay Classic receivers.
- Discover newer AirPlay-only receivers such as Roku, enter their on-screen PIN,
  and send authenticated encrypted audio. Pairing keys use the system credential
  store; reconnects reuse the pairing without saving the PIN in settings.
- Play compatible originals on Google Cast devices, with receiver-driven progress,
  transport controls and temporary media URLs that keep server credentials private.
  Explicit certificate pins support owner-operated software Cast targets.

AirPlay grouping, legacy PIN/password schemes and Cast speaker groups are not implemented. Chromecast
decodes originals and therefore uses its own codec support, without Sonicfast EQ
or visualization. The software Cast fixture is not a certified Chromecast; physical
Google Cast hardware and Google SDK interoperability need separate validation.

Snapcast is opt-in and uses unencrypted TCP on a trusted network. Authenticated/TLS
Snapcast transports, Opus/Vorbis receiving and remote song/queue control are not
implemented. Room playback retains the server's configured buffer latency.

Linux has automated PCM/FLAC Docker transport and software-playout coverage.
Physical-speaker synchronization and Windows/macOS playback need validation;
Docker's virtual/file outputs do not establish hardware synchronization accuracy.
Updates remain manual; the in-app self-updater stays disabled.
