Sonicfast 0.16.0 adds MPD as an audio output and makes self-hosted Cast receivers and Snapcast easier to set up.

- Play your queue on an **MPD server** (Music Player Daemon), for example on a
  Raspberry Pi. MPD servers on your network appear in the output picker, or enter
  a host and port (normally 6600) in Settings → Casting. MPD fetches a temporary
  link to the original file from Sonicfast and decodes it; your music-server
  sign-in never reaches it. Pause, seek, volume and next song use the normal
  controls, and MPD's own clients show the song title, artist and album.
- Trust a **self-hosted Cast receiver** in one click: the dialog now shows the
  certificate fingerprint the receiver presented, with **Trust receiver** (pasting
  one is still available). The new **Trust self-hosted Cast receivers** setting
  trusts a new receiver the first time without asking. A receiver whose
  certificate later changes always asks again.
- Output picker rows show a small AirPlay, Cast or MPD tag, so same-named
  receivers are easy to tell apart. Long names end in "…" instead of running into
  the check mark, and MPD's default `Music Player @ host` names show just the host.
- Settings → Snapcast replaces **Send music** with a **Snapcast output** switch,
  which lists Snapcast in the output picker; choose it there to start sending.
  Settings saved while sending keep Snapcast listed. A new **How Snapcast works**
  dialog explains sending, receiving and using both.
- Settings now has an **About** section with the running version and links to its
  release notes, keyboard shortcuts and source code.

MPD plays one song at a time and replaces the MPD server's current queue. Like
Chromecast, it decodes the original file, so EQ and visualization do not apply.
Seeking needs a music server that offers byte ranges for originals; otherwise
the song keeps playing from where MPD is. Password-protected MPD servers are not
supported yet.

Validation: Linux automated tests passed. The Docker interoperability tests
passed for AirPlay, the self-hosted Cast receiver (including the trust check and
the fingerprint it presents) and a real MPD 0.24.8 server, which the app drove
through output switches, pause, seek, resume, song end and replay. One earlier
run failed in the AirPlay check when its short test tone ended mid-switch; the
rerun passed. MPD has been used on the owner's Raspberry Pi (MPD 0.24.0); Cast
trust from the picker on a physical receiver and Windows/macOS were not tested.

Install updates manually; the in-app self-updater remains disabled.
